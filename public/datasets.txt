# Copernicus Browser — Dataset and layer ids

Every `datasetId` and `layerId` that can be used in a Browser link in the default theme (`themeId=DEFAULT-THEME`). Use these ids exactly as written (they are case-sensitive) and never invent one: an unknown `datasetId` makes the Browser show "Selected dataset does not exist!" and silently switch to Sentinel-2 L2A. See deep-linking.txt for the other parameters.

This file is generated by `npm run generate-datasets` from the app's own configuration. Do not edit it by hand.

Layer ids can differ between themes. The ids below are the ones for the default theme.

The example links use a fixed placeholder position (zoom 11 near Lake Maggiore). Replace `lat`, `lng` and `zoom` with the place the user asked for: a dataset with only regional coverage finds no image at the placeholder.

## Do not use these ids

These ids look plausible but do not exist.

- `S1_AWS_IW_VVVH`: use `S1_CDAS_IW_VVVH` instead (there is no AWS Sentinel-1 dataset)
- `S1_AWS_*`: use `S1_CDAS_*` instead (use the S1_CDAS_* ids listed below)
- `LOTL1_CDAS`: use `CDAS_L8_L9_LOTL1` instead (Landsat 8-9 Level-1)
- `LANDSAT_8_9_CDAS`: use `CDAS_L8_L9_LOTL1` instead (Landsat 8-9 Level-1)
- `MODIS_CDAS`: no replacement (no MODIS dataset exists in the Browser)
- `S2_WORLDCOVER_ANNUAL_CDAS`: use `65d4af89-5ce5-468e-bbbe-8a2fd9efaccc` instead (WorldCover annual cloudless mosaic)
- `ESA_WORLDCOVER_CDAS`: use `65d4af89-5ce5-468e-bbbe-8a2fd9efaccc` instead (WorldCover annual cloudless mosaic)
- `CCM_VHR_OPTICAL_PLEIADES`: no replacement (Contributing Missions VHR ids are CCM_VHR_IMAGE_<year>)
